# Groq provider integration

Groq is an explicit provider choice alongside Gemini and OpenAI. The configured model is `openai/gpt-oss-120b`, returned by the authenticated Groq model list and verified with a small structured-output request on 16 November 2026. Requests use Groq's OpenAI-compatible endpoint with no cross-provider fallback. Scene edits, generation tests, source metadata, persisted settings and saved-story validation support Groq.

## Verification

- Full `npm test` and `npm run build` passed. Targeted routing, authentication, rate-limit classification and Groq scene-regeneration tests passed after final test changes.
- Isolated browser: Groq selection, key placeholder, persistence, provider mismatch handling and 320/390px reflow passed using fake credentials and no provider requests.
- Real Groq authentication and a small JSON generation succeeded.
- Full B.Com vs BBA / Trust / English storyboard attempts were blocked by Groq's 8,000 tokens-per-minute limit. No complete generated storyboard or creative score was verified. A material improvement in creative reliability is not claimed.

The account's rate-limit message included a billing help URL. Explicit `rate_limit` error codes now take precedence over message keywords, so that response is displayed as a rate limit rather than a billing failure. Free-tier limits are account-specific; no billing changes or paid fallback were introduced.

The supplied credential was used only in a temporary private file for direct Groq requests, never committed or embedded in the frontend. Users must enter their own key in AI settings. A key shared in chat should be replaced after testing.
